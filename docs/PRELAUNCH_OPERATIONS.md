# 소망교회 추모관 개시 전 운영 기준

이 문서는 기능 설명서가 아니라, 서비스가 오래 안전하게 운영되기 위한
기준이다. 비밀번호, 서버 주소, 데이터베이스 주소와 같은 비밀값은 이
문서나 저장소에 적지 않는다.

## 현재 운영 단위

- 키오스크와 웹은 같은 API와 MySQL 데이터베이스를 사용한다.
- 사진 파일은 현재 서버의 업로드 저장소에 보관된다.
- 공개 추모관은 `published` 상태이면서 `public` 공개 설정인 경우에만
  일반 웹 목록과 검색에 표시된다.
- 회원이 새로 만든 추모관은 관리자 검토 전 `pending` 상태와 비공개로
  유지한다.
- 새 편지는 관리자 확인 전 `hidden` 상태로 저장한다.

## 개시 전에 완료해야 하는 외부 운영 작업

1. HTTPS 도메인을 연결하고 HTTP 접근은 HTTPS로 보낸다.
2. 앱 포트는 외부에 직접 열지 않고, HTTPS 역방향 프록시만 외부에
   노출한다.
3. 서버 관리자 계정과 데이터베이스 관리자 계정의 기존 비밀번호를
   교체한다.
4. 앱에는 MySQL root 계정이 아닌 추모관 전용 제한 계정을 사용한다.
5. 매일 데이터베이스 백업, 업로드 파일 백업, 복구 확인 일정을 만든다.
6. 서버 응답, 디스크 사용량, 백업 실패를 알려 주는 외부 감시를 둔다.
7. 키오스크 PC는 일반 Windows 화면이 아닌 전용 전체 화면 모드로
   실행한다.

## 이용자가 늘어날 때의 확장 순서

1. 이미지 파일을 서버 디스크에서 객체 저장소로 옮긴다.
2. 요청 제한을 메모리 방식에서 Redis 같은 공용 저장소 방식으로 바꾼다.
3. 추도일 문자 발송 작업에 데이터베이스 잠금을 추가해 서버가 여러
   대여도 한 번만 발송되게 한다.
4. 읽기 요청이 많아지면 앱 서버를 여러 대로 늘리고, 앞단에 로드밸런서를
   둔다.

## 공개 검토 절차

1. 사용자가 기념관 또는 편지를 작성한다.
2. 관리자가 관리자 화면에서 내용과 공개 범위를 확인한다.
3. 기념관은 공개와 게시 상태를 함께 변경해야 일반 검색에 표시된다.
4. 편지는 공개 상태로 바꾼 뒤에만 화면에 표시된다.
5. 게시 중인 사용자 기념관의 수정은 관리자가 확인하여 반영한다.

## 배포 전 확인

- 타입 검사, 자동 테스트, 운영 빌드가 모두 통과했는지 확인한다.
- HTTPS 주소, 키오스크 검색, 비공개 비밀번호, 편지 접수, 관리자 공개를
  실제 화면에서 확인한다.
- 배포 직전 DB 백업과 이전 앱 릴리스를 유지한다.
