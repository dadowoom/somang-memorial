# 회원 작성 흐름 개선 인계

2026-09-07 작업. 문의 전화번호와 상담 시간은 담당자 확인 후 별도로 추가합니다.

## 화면 변경

- 추모관 작성: 개인 기기 확인 후 임시저장·불러오기, 마지막 저장 시각, 저장하지 않은 변경 안내.
- 임시저장은 같은 브라우저·같은 계정에서만 사용합니다. 다른 PC로 글을 이어쓰는 기능은 아닙니다.
- 공용 기기에 자동 저장하지 않습니다. 입장 비밀번호와 관리자 메모는 저장본에서 제외합니다.
- 이전 형식의 저장본은 본인 글인지 확인한 뒤 명시적으로 불러옵니다. 읽지 못한 저장본은 자동 삭제하지 않습니다.
- 같은 탭에서 브라우저 뒤로·앞으로 이동할 때 작성 글을 메모리에 유지합니다. 새로고침·닫기 전에 임시저장이 필요합니다.
- 등록 완료 후 사진 추가 화면으로 이동할 수 있습니다. 본인이 만든 추모관이면 확인 대기 중이든 게시된 뒤든 사진을 준비하고 고칠 수 있습니다.
- 사진 바로가기는 화면을 불러온 뒤 사진 영역으로 이동합니다. 페이지 맨 위에서 사진을 다시 찾을 필요가 없습니다.
- 사진은 회원 기준 최대 30장입니다. 첫 사진을 대표 사진으로 지정하며, 사진 설명·연도·순서·대표 사진을 변경할 수 있습니다.
- 사진 업로드 결과를 확인하지 못한 경우 해당 파일을 안내합니다. 목록을 먼저 확인하고 빠진 사진만 재선택합니다.
- 내 추모관: 상태에 따라 이어서 수정, 사진 추가, 가족관 관리, 공개 주소 공유를 구분합니다. 본인 추모관이면 게시된 뒤에도 수정과 사진 추가가 열려 있습니다.
- 수정 요청 안내는 상태를 알 수 없는 예외 상황에만 나타납니다. 전달할 문구를 만드는 도구이며 자동 접수 기능이 아닙니다.
- 로그인 화면: 이미 가입한 분과 처음 이용하는 분의 선택을 분리합니다. 추모관 작성으로 이동할 때 로그인 화면을 기본으로 표시합니다.

- 비공개 추모관의 공개 검색·본문 접근 규칙은 변경하지 않습니다.

- DB 구조와 마이그레이션 파일, 운영 설정은 변경하지 않습니다. 실제 사진 기능 사용 시 기존 사진 테이블과 파일 저장소를 사용합니다.
- 이 작업은 작업 브랜치에서 검토합니다. main 병합 승인과 운영 배포 요청은 별도입니다.

## 가족 초대 (2026-09-13 추가)

- 추모관 주인이 내 추모관의 **가족 초대** 버튼에서 초대 링크를 만든다. 링크는 7일 동안 쓸 수 있고 여러 가족이 같은 링크로 들어올 수 있다. 새 링크를 만들면 이전 링크는 닫힌다.
- 링크 원문은 저장하지 않고 해시만 저장한다(비밀번호 재설정 링크와 같은 방식). 그래서 만든 직후 한 번만 보여 주고, 잃어버리면 새로 만든다.
- 링크로 들어온 가족은 로그인(또는 가입) 뒤 "함께 관리하기"를 누르면 `memorial_family_members`에 들어간다. 그 뒤로 글·사진·가족관을 주인과 똑같이 고치고, 내 추모관에 "함께 관리" 표시로 나타난다.
- 초대와 가족 제외는 **주인과 관리자만** 한다. 초대받은 가족이 또 초대하면 주인이 누가 들어왔는지 알 수 없기 때문이다. 본인이 나가는 것은 누구나 할 수 있다.
- 참여·제외·나감은 감사기록(`memorial.family.join` / `remove` / `leave`)으로 남는다.
- 우리 부모님 찾기에서 이미 다른 가족이 시작한 추모관이면 "먼저 시작한 가족에게 초대 링크를 받으라"고 안내한다.
- 권한 판단은 `shared/memorialFamilyPermissions.ts` 한 곳에 있다. 사진첩·가족관 권한 함수는 이것을 부른다.

## 확인 방법

1. `pnpm check`, `pnpm test`, `pnpm build`를 실행합니다. 테스트는 실제 DB를 연결하지 않는 대체 데이터로 검사합니다.
2. 개인 기기 확인 없이 임시저장을 눌렀을 때 안내만 나타나는지 확인합니다.
3. 임시저장 후 새 탭에서 본인 글을 직접 불러오고, 저장 시각을 확인합니다. 다른 계정에서는 기존 계정의 글이 표시되면 안 됩니다.
4. 작성 중 뒤로·앞으로 이동하고, 저장하지 않고 나가기·로그아웃·새로고침할 때 경고를 확인합니다. 브라우저 종류에 따라 닫기 경고가 제한될 수 있으므로 임시저장을 기본으로 안내합니다.
5. 5단계 최종 확인 전에는 등록되지 않아야 합니다. 등록 버튼을 누른 뒤 중복 등록과 작성 버튼 재활성화가 없어야 합니다.
6. 본인 추모관에서 확인 대기 중과 게시된 뒤 모두 사진 추가를 확인합니다. 다른 사람의 추모관에서는 회원 사진 변경을 허용하면 안 됩니다.
7. 휴대폰 너비에서 사진 버튼과 내 추모관의 다음 행동 안내를 확인합니다.
8. 공개 추모관만 공유 버튼을 표시하고, 수정 요청 문구가 자동 접수로 오해되지 않는지 확인합니다. 자동 복사가 지원되지 않는 브라우저에서는 직접 복사 안내가 나와야 합니다.

로컬 확인 기록: 자동검사 232개 통과, 형식 검사와 빌드 통과. 운영 DB와 분리한 시험 화면에서 저장·불러오기, 뒤로·앞으로 이동, 최종 등록 1회, 사진 업로드, 상태별 안내, 로그인 전환 및 390px 화면을 확인했습니다.

추가 확인: 처음에는 브라우저 자동화 도구가 나가기 경고창을 조작하지 못했습니다. 후속 확인에서 경고창이 닫힌 뒤에도 작성 화면과 입력한 시험 글이 그대로 유지되는 것을 실제 브라우저에서 확인했습니다. 이 나가기 동작의 추가 확인은 완료했습니다.

## 별도 준비

- 도메인·HTTPS는 별도 운영 작업입니다. 도메인 구매만으로 HTTPS 적용이 완료되지는 않습니다.
- 문의 전화번호·상담 시간은 사용자 제공 대기입니다. 확인되지 않은 번호는 넣지 않습니다.
- 서버 저장형 작성 초안, 문의 자동 접수, 실제 이용자 대상 사용성 검사는 이번 변경에 포함하지 않습니다.
