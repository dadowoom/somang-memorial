# 프로젝트 현황 & 협업 기준

이 문서는 이 저장소에서 함께 작업하는 도구(Claude, Codex)와 관리자가
같은 상태를 공유하고 충돌 없이 이어가기 위한 **살아있는 문서**다.
작업이 진행되면 최신 상태로 갱신한다.

> **보안 취약점 상세, 서버 접속정보, 비밀번호 등 민감한 내용은 이 문서(공개 저장소)에 적지 않는다.**
> 그런 내용은 별도의 비공개 문서로만 관리한다.

---

## 1. 역할 분담

- **Claude**: 코드 조사·수정·PR 작성, 운영 사이트 **읽기 전용** 확인. 운영 서버·DB에 직접 접속하지 않는다.
- **Codex**: 서버에서 배포와 DB 작업(정리·마이그레이션·백업)을 실행한다.
- **관리자(사용자)**: 두 도구 사이의 조정자. 승인·결정을 내리고, "지금 어느 쪽에서 작업하는지"를 알려준다. 비개발자이므로 쉬운 한국어로, 한 번에 하나씩 설명한다.

## 2. 충돌 방지 규칙

1. 작업 시작 전 항상 `git fetch origin main` 후 최신 기준으로 시작한다.
2. 한 번에 한 곳에서만 크게 작업한다. 옮길 때는 관리자가 알려준다.
3. **main에 직접 커밋하지 않는다.** 브랜치 → 검증 → PR → **관리자 승인** → 병합.
4. 병합이 끝난 브랜치는 삭제한다.
5. 진행 중인 PR이 어떤 파일을 건드리는지 서로 인지해, 같은 파일을 동시에 바꾸지 않는다.
6. 위험 작업(DB 삭제·마이그레이션·비밀번호 변경·서버 초기화)은 **백업 먼저 + 관리자 확인 먼저**, Codex만 실행한다.
7. 비밀값(서버·DB 비밀번호, API 키, 세션 시크릿)은 채팅·로그·코드·저장소 어디에도 남기지 않는다.
8. 코드 수정마다 검증 3종: `pnpm run check` / `pnpm test` / `pnpm run build`.
9. 로컬 `.codex_tmp/`는 임시 폴더 — 읽지도 수정하지도 커밋하지도 않는다.

## 3. 현재 상태 (요약)

- **데이터 정리 완료.** 개발용으로 만들어졌던 예시/가짜 추모관을 모두 제거했고, 실제 예시 추모관 1개(`kim-somang-kwonsa`)만 정상 운영 중이다.
- **개시 준비 단계.** 개시를 막는 문제는 없다. `/healthz`·`/readyz` 정상.
- **main과 운영 서버가 같은 상태다.** #31(내 부모 찾기)은 배포 완료. 운영 화면 코드에서
  새 문구(`생년월일 (선택)`)와 옛 문구 제거를 모두 확인했다.

## 4. 열린 PR (개시 후 배포 예정)

- **#24** 첫 화면 속도 개선 — 개발용 도구를 운영 빌드에서 제외 + 응답 압축(gzip).
- **#25** 운영 접속 로그 + 중앙 오류 처리 미들웨어.
- 두 PR 모두 `server/_core/index.ts`를 함께 건드린다. **각각은 main과 깨끗이 합쳐지지만 서로는 충돌한다.**
  하나를 먼저 병합하고 나머지를 다시 맞춘 뒤 검증 3종을 다시 돌린다. 순서는 **#24 → #25**.
- 방문이 적은 시간에 **하나씩** 배포하고 매번 화면을 확인, 이상 시 즉시 롤백한다.
- **#30** 안장 기록 이름에서 직분 분리 — Codex 작업. 아래 5절 참고.

## 4-1. 내 부모 찾기 (`/my/find-parent`)

원본 안장 기록의 특성 때문에 두 단계로 나눠 개선한다.

- 소망동산 안장자 2,209명 중 **792명(36%)은 생년월일이 없다**(`0000-00-00`로 저장).
- 이름 열에 직분이 섞여 있는 경우가 **약 13%** 있다(예: `이한수 장로(타)`).

**1단계 — #31 (병합·배포 완료).** 생년월일을 **선택 입력**으로 바꾸고 이름 **부분일치**로 검색한다.
생년월일이 없는 분도 이름만으로 찾을 수 있고, 직분이 붙은 이름도 검색은 된다.

**2단계 — #30 (아직 시작 전).** 화면에 보이는 이름에서 직분을 떼어 `이한수`처럼 정리한다.

> ⚠️ **#30 작업 시 주의.** `getSomangIntermentRecordForClaim`은 이름을 정확히 일치로 대조하고,
> 화면은 추모관 생성 시 검색 결과의 이름을 그대로 되돌려 보낸다. 표시 이름에서 직분을 떼면
> 이 대조가 실패해 추모관 생성이 깨진다. 정확 일치 대신 `isSameIntermentPersonName`으로 비교할 것.
> 또한 DB의 `nameNormalized` 열은 import 스크립트가 **공백만 제거**해 채우므로 직분이 남아 있다.
> import 스크립트의 정규화는 이번 작업에서 건드리지 않는다(바꾸면 기존/신규 데이터 기준이 갈린다).

## 5. 남은 작업 (개요)

- **백업 자동화** — 서버의 데이터베이스와 업로드 사진을 매일 외부 클라우드 저장소에 백업(코드는 저장소에 있으므로 제외). 오래된 백업본은 자동 정리. 저장 위치는 **운영 서버와 다른 곳**이어야 한다. 접근 키는 저장소에 넣지 않고 서버 환경변수로만 둔다.
- **HTTPS 연결** — 도메인 구매 후 진행. (그 전까지 도메인·DNS·방화벽을 임의로 바꾸지 않는다.)
- **데이터베이스 재구축 정합성** — 새 환경에서 처음부터 구축할 때를 대비한 마이그레이션 정리. 운영 DB 상태 확인 후 Codex가 처리.
- **성장 대비/보안 하드닝** — 상세 항목은 별도 비공개 진단 문서로 관리한다.

## 6. 새 세션 시작 체크리스트

1. `git fetch origin main` 후 main 최신 커밋 확인.
2. `gh pr list`로 열린 PR 확인. 서로 겹치는 PR이 있으면 **그것부터 정리**한다.
   겹침 여부는 `git merge-tree --write-tree --name-only origin/main origin/<브랜치>`로 미리 확인할 수 있다.
3. 필요하면 운영 사이트를 읽기 전용으로 확인.
4. 관리자에게 "지금 무엇부터 할지" 확인 후 한 번에 하나씩 진행.

> 관리자는 작업 PC를 오갈 수 있다(윈도우/맥). **저장소 밖의 파일에 의존하지 않는다** —
> 원본 소천자 엑셀 등은 특정 PC에만 있으므로, 필요한 사실은 이 문서에 적어 남긴다.
> 맥에는 MySQL이 없어 서버 로컬 실행·마이그레이션 테스트가 안 된다. 검증 3종까지만 하고
> 운영 확인은 읽기 전용으로 한다.
